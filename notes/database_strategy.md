## 2. 各功能模块的数据存储需求分析

### 2.1 Team (团队)

**适合存储方式: 关系型数据库**

**核心数据表:**
- `teams` - 团队基本信息
- `team_members` - 团队成员关系
- `team_invitations` - 团队邀请
- `member_roles` - 角色定义 

**设计理由:** 
- 团队与成员之间存在明确的关系
- 需要强一致性保证权限数据准确性
- 涉及用户管理和权限控制，需要事务保证

### 2.2 Security (安全与合规)

**混合存储方案:**

**关系型数据库:**
- `access_policies` - 访问控制策略
- `data_retention_policies` - 数据保留策略
- `ip_allowlists` - IP白名单
- `security_audit_logs` - 安全审计日志 (关键操作)

**文档型数据库:**
- `detailed_security_logs` - 详细安全日志记录

**本地存储 (IndexedDB):**
- 安全设置的本地缓存
- 非敏感的配置首选项

**设计理由:**
- 安全策略需要高一致性和事务支持
- 详细日志数据量大且格式可能多变
- 部分安全设置可以缓存提高响应速度

### 2.3 CRM (客户关系管理)

**混合存储方案:**

**关系型数据库:**
- `contacts` - 联系人基本信息
- `companies` - 公司信息
- `deals` - 销售机会/交易
- `activities` - 活动记录
- `tags` - 标签管理

**文档型数据库:**
- `interaction_history` - 详细交互历史
- `contact_notes` - 联系人笔记
- `custom_fields` - 自定义字段配置

**本地存储 (IndexedDB):**
- 联系人列表缓存
- 最近查看的联系人
- 用户自定义视图设置

**设计理由:**
- 核心CRM数据需要关系型结构和强一致性
- 非结构化内容(笔记、交互历史)适合文档存储
- 频繁访问的数据可本地缓存提升性能

### 2.4 Event (事件管理)

**混合存储方案:**

**关系型数据库:**
- `events` - 事件基本信息
- `event_participants` - 参与者关系
- `event_categories` - 事件分类

**文档型数据库:**
- `event_details` - 丰富的事件详情
- `event_resources` - 事件相关资源

**本地存储 (IndexedDB):**
- 事件日历视图缓存
- 用户创建的事件草稿
- 个人事件偏好设置

**设计理由:**
- 核心事件数据需要关系支持
- 详细描述和资源更适合灵活的文档存储
- 本地缓存日历视图提升性能

### 2.5 Billing (账单与订阅)

**适合存储方式: 关系型数据库**

**核心数据表:**
- `subscriptions` - 订阅信息
- `billing_history` - 账单历史 
- `payment_methods` - 支付方式
- `pricing_plans` - 价格方案

**设计理由:**
- 财务数据要求ACID事务保证
- 需要严格的数据一致性和完整性
- 关系模型更适合处理账单历史和订阅关系

### 2.6 Notification (通知中心)

**混合存储方案:**

**关系型数据库:**
- `notification_settings` - 通知设置
- `notification_types` - 通知类型定义

**文档型数据库:**
- `user_notifications` - 用户通知内容

**本地存储 (IndexedDB):**
- 已读/未读状态
- 通知首选项
- 最近通知缓存

**设计理由:**
- 设置和类型定义需要结构化存储
- 通知内容格式多变且数量大
- 通知状态更适合本地存储并定期同步

### 2.7 Settings (用户设置)

**混合存储方案:**

**关系型数据库:**
- `user_settings` - 核心用户设置
- `app_settings` - 应用全局设置

**本地存储 (IndexedDB):**
- UI偏好和主题设置
- 布局配置
- 最近使用的设置

**设计理由:**
- 核心设置需要在设备间同步
- UI偏好适合本地存储快速访问
- 大部分设置变更频率低，适合混合策略

### 2.8 Template (邮件模板)

**混合存储方案:**

**关系型数据库:**
- `templates` - 模板基本信息
- `template_categories` - 模板分类
- `template_sharing` - 模板共享权限

**文档型数据库:**
- `template_content` - 模板详细内容
- `template_versions` - 模板历史版本

**本地存储 (IndexedDB):**
- 模板编辑草稿
- 常用模板缓存
- 模板预览缓存

**设计理由:**
- 模板元数据适合关系型结构
- 模板内容可能包含复杂HTML/JSON，适合文档存储
- 编辑过程中的草稿适合本地存储提高编辑性能

## 3. 数据存储策略详解

### 3.1 关系型数据库适用场景

以下数据类型适合存储在关系型数据库(如MySQL, PostgreSQL)中:

- **核心业务实体数据**:
  - 用户账户信息
  - 团队和组织结构
  - 权限和角色定义
  - 账单和订阅信息
  
- **需要事务保证的数据**:
  - 财务和支付记录
  - 安全与访问控制策略
  - 数据保留和合规设置
  
- **强结构化且关系复杂的数据**:
  - CRM中的联系人与公司关系
  - 事件与参与者关系
  - 模板分享权限
  
- **需要高度一致性的数据**:
  - 用户认证信息
  - 团队成员角色
  - 计费信息

### 3.2 文档型数据库适用场景 

以下数据类型适合存储在文档型数据库(如MongoDB, Firestore)中:

- **结构灵活多变的数据**:
  - 邮件模板内容
  - CRM客户交互记录
  - 通知内容
  
- **大量非结构化或半结构化数据**:
  - 安全审计日志
  - 事件详细描述
  - 用户自定义字段
  
- **需要频繁扩展Schema的数据**:
  - 自定义表单响应
  - 插件生成的数据
  - 集成第三方服务的数据
  
- **层级嵌套数据**:
  - 组织层次结构
  - 复杂设置配置
  - 模板版本历史

### 3.3 本地存储 (IndexedDB) 适用场景

以下数据类型适合使用本地存储:

- **常用/频繁访问的数据缓存**:
  - 联系人列表
  - 最近使用的模板
  - 事件日历视图
  
- **离线操作需要的数据**:
  - 编辑中的草稿
  - 待同步的变更
  - 基本工作数据
  
- **UI状态和偏好设置**:
  - 主题和布局首选项
  - 展开/折叠状态
  - 分页和排序偏好
  
- **不需要跨设备同步的用户个性化设置**:
  - 本地通知偏好
  - 仪表盘小组件配置
  - 最近查看历史

## 4. 数据同步与离线策略

### 4.1 IndexedDB与在线数据库同步方案

对于弱交互性内容，建议采用以下同步策略:

#### 基本同步框架

```
┌───────────────────┐   ┌─────────────┐   ┌───────────────┐
│ 用户操作/数据变更  │──▶│ IndexedDB  │◀──▶│ 同步控制器   │
└───────────────────┘   └─────────────┘   └───────┬───────┘
                                                 │
                            ┌─────────────────────v─────────────────┐
                            │ 网络状态检测、冲突解决、批量同步策略  │
                            └─────────────────────┬─────────────────┘
                                                 │
┌────────────────┐   ┌───────────────────────────v───────────────────────┐
│ 服务器数据库   │◀──▶│ REST API / GraphQL / WebSockets / Server Actions │
└────────────────┘   └───────────────────────────────────────────────────┘
```

#### 同步策略详解

1. **增量同步**:
   - 仅同步变更数据而非全量数据
   - 使用时间戳或版本标识跟踪变更
   - 减少网络传输和服务器负载

2. **批量处理**:
   - 累积多个变更后一次性提交
   - 减少API调用次数
   - 适用于弱交互场景如CRM笔记、模板编辑

3. **优先级同步**:
   - 对不同类型数据设置同步优先级
   - 核心业务数据优先同步
   - 非关键数据可延迟同步

4. **冲突解决策略**:
   - 乐观锁 - 时间戳或版本号比较
   - 合并策略 - 自动合并非冲突字段
   - 用户干预 - 提示用户解决冲突

### 4.2 适用IndexedDB的具体功能

下面列出每个模块中适合使用IndexedDB的具体功能:

#### CRM模块
- **联系人列表缓存** - 常用联系人本地存储
- **最近互动历史** - 保存最近50条互动记录
- **搜索历史** - 记录用户搜索模式
- **视图配置** - 保存用户自定义列表视图

#### 邮件模板模块
- **模板编辑器状态** - 保存编辑进度
- **常用模板** - 缓存最常用的5-10个模板
- **模板草稿** - 自动保存未完成编辑
- **自定义组件库** - 用户创建的组件

#### 事件模块
- **日历视图缓存** - 当前月份事件数据
- **事件草稿** - 未完成创建的事件
- **个人事件过滤器** - 用户定义的事件过滤

#### 通知模块
- **通知状态** - 已读/未读状态
- **通知偏好** - 展示和排序设置
- **消息预览缓存** - 通知内容预览

## 5. 实现建议和技术选择

### 5.1 技术栈推荐

1. **关系型数据库**:
   - PostgreSQL - 强大的开源关系型数据库，支持JSON
   - MySQL/MariaDB - 广泛使用的关系型数据库

2. **文档型数据库**:
   - MongoDB - 灵活的文档存储
   - Firebase Firestore - 实时数据库，适合协作功能

3. **IndexedDB 工具库**:
   - Dexie.js - 简化IndexedDB使用的库
   - localForage - 提供统一的本地存储API

4. **同步框架**:
   - SWR/React-Query - 数据获取和缓存
   - PouchDB/RxDB - 支持离线优先和同步
   - Workbox - 管理服务工作线程和缓存

### 5.2 数据库设计最佳实践

1. **关系型数据库**:
   - 使用外键确保数据完整性
   - 设计适当的索引提高查询性能
   - 考虑分表策略处理大量数据

2. **文档型数据库**:
   - 避免过深的嵌套结构
   - 设计合理的分片策略
   - 根据访问模式优化文档结构

3. **IndexedDB**:
   - 定义明确的数据过期策略
   - 实现数据大小限制机制
   - 创建适当的索引加速查询

## 6. 总结

Mail Box应用的数据库设计需要综合考虑数据特性、访问模式和用户体验。通过混合使用关系型数据库、文档型数据库和本地存储，可以实现高性能、良好用户体验和数据一致性的平衡。

核心原则:
- 将结构化和关系性强的数据存储在关系型数据库
- 将灵活多变的非结构化数据存储在文档型数据库
- 将频繁访问和离线操作数据缓存在IndexedDB
- 实施智能同步策略减少网络传输和提高响应速度

这套策略和方案可根据实际用户需求和使用模式进行调整和优化。
