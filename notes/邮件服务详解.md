## 三、数据流程

### 1. 邮件获取流程

```
UI组件 → React Hooks → API路由 → 增强型服务 → 基础服务 → Nylas API
       ↑                                    ↓
       └───────── 缓存系统(多级) ───────────┘
```

**关键节点**:
1. **组件请求**：`MailScroll.tsx`中通过`useEmails` hook请求数据（第80行）
2. **Hook层请求**：`use-mail-queries.ts`中的`useEmails`发起fetch请求（第132行）
3. **API层处理**：`inbox/route.ts`接收请求并路由到增强型服务（第32行）
4. **缓存检查**：`mail-service-enhanced.ts`检查缓存是否命中（第20行）
5. **API请求**：缓存未命中时，发起真实API请求（第24行）
6. **结果缓存**：将API结果存入缓存（第28行）
7. **数据返回**：沿原路径返回数据到UI组件

### 2. 邮件详情获取流程

```
UI组件 → 本地缓存检查 → API请求(如需) → 更新UI
```

**关键节点**:
1. **本地缓存检查**：`use-mail.ts`中的`getEmail`方法先检查本地缓存（第133-143行）
2. **组件状态合并**：`MailScroll.tsx`中`currentEmail`合并多个数据源（第98-112行）
3. **按需API请求**：只有当需要详细数据时才发起API请求（第87-91行）

### 3. 缓存机制(多级)

```
服务器内存缓存 → IndexedDB缓存 → React Query缓存 → 组件状态缓存
```

**关键节点**:
1. **服务器缓存**：`cache-manager.ts`中的内存Map实现服务器缓存（第13行）
2. **持久化缓存**：`enhanced-mail-service.ts`使用IndexedDB缓存（第213行）
3. **React Query**：`use-mail-queries.ts`利用React Query内置缓存（第132行）
4. **组件状态**：`use-mail.ts`中的`emailCache`状态存储（第37行）
